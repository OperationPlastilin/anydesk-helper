# anydesk-helper

ИИ-агент техподдержки. Вы даёте ему **ID AnyDesk** и **задачу** («установить Microsoft Office»),
он подключается, смотрит на экран удалённого компьютера, составляет короткий план, задаёт вам
вопросы (какая лицензия, какой логин…) и выполняет его сам — мышью, клавиатурой и через
PowerShell на компьютере пользователя.

Мозг — бесплатная vision-модель **Qwen-VL**: локально через Ollama или через бесплатный API.

```
 ваш ПК (Windows)                                              ПК пользователя
┌──────────────────────────────────────────────┐   AnyDesk   ┌────────────────┐
│ anydesk_helper ──скриншот окна──▶ Qwen-VL     │◀──────────▶│  рабочий стол,  │
│      ▲                              │         │             │  PowerShell,    │
│      │ ответ: {"action":"click",...}│         │             │  установщики    │
│      └────── мышь / клавиатура ─────┘         │             └────────────────┘
│                    ▲ вопросы / подтверждения                │
│                    └──────────── вы (оператор)              │
└──────────────────────────────────────────────┘
```

## Как это работает

1. Программа запускает `AnyDesk.exe <ID>` и ждёт, пока пользователь примет подключение
   (или подключается сама по паролю неконтролируемого доступа).
2. **План.** Модель получает скриншот и задачу, отвечает: как поняла задачу, какие вопросы к вам
   и план из 3–10 шагов (с готовыми командами PowerShell). Вы отвечаете на вопросы и можете
   поправить план.
3. **Цикл.** Скриншот → модель выбирает одно действие → программа его выполняет → новый скриншот…
   Действия: `click`, `double_click`, `drag`, `scroll`, `type` (вставка текста), `key`
   (сочетания клавиш), `open_terminal` (Win+R → PowerShell/cmd, в т.ч. от администратора),
   `wait`, `ask_user` (вопрос вам), `done`, `fail`.
4. Когда модель считает, что всё готово, она проверяет результат на экране, а вы подтверждаете.

Для типовых задач есть «методички» в папке `playbooks/` — они подмешиваются в промпт по ключевым
словам из задачи (например, `office.md` для «установить офис»: проверка уже установленного Office,
установка через официальный Office Deployment Tool, выбор редакции, активация). Добавляйте свои:
первая строка — `keywords: слово1, слово2`, дальше любые подсказки и команды.

## Установка (на компьютере техника, Windows 10/11)

1. Установите [Python 3.11+](https://www.python.org/downloads/) (галочка «Add to PATH») и AnyDesk.
2. Скачайте этот репозиторий и запустите `install.bat` — он создаст `.venv`, поставит зависимости
   и скопирует `config.example.toml` в `config.toml`.
3. Выберите модель (ниже) и пропишите её в `config.toml`.
4. Проверьте модель: `run.bat --check` — программа нарисует картинку и проверит, что модель её
   видит и правильно называет координаты.

### Какую модель взять (бесплатно)

| Вариант | Что сделать | `config.toml` |
|---|---|---|
| **Ollama (локально)** — данные никуда не уходят | [ollama.com](https://ollama.com) → `ollama pull qwen2.5vl:7b` (нужна видеокарта ~8 ГБ) | `base_url = "http://localhost:11434/v1"`, `model = "qwen2.5vl:7b"`, `coords = "pixels"` |
| Ollama, Qwen3-VL | `ollama pull qwen3-vl:8b` | `model = "qwen3-vl:8b"`, `coords = "norm1000"` |
| **OpenRouter** | ключ на openrouter.ai, модели с суффиксом `:free` | `base_url = "https://openrouter.ai/api/v1"`, `model = "qwen/qwen2.5-vl-72b-instruct:free"`, `api_key = "..."` |
| **Alibaba Model Studio (DashScope)** | бесплатная квота для новых аккаунтов | `base_url = "https://dashscope-intl.aliyuncs.com/compatible-mode/v1"`, `model = "qwen-vl-max"`, `api_key = "..."` |

Важно про `coords`: Qwen2.5-VL отвечает координатами в пикселях (`pixels`), Qwen3-VL — в
относительных единицах 0..1000 (`norm1000`). Если `--check` показывает большой промах —
попробуйте другое значение.

Честно о качестве: маленькие локальные модели (7–8B) неплохо понимают экран и пишут команды, но
промахиваются мимо мелких кнопок. 72B-модели через API работают заметно надёжнее. Поэтому агента
просят по возможности работать через PowerShell/winget, а не кликать по окнам.

## Запуск

```bat
run.bat --id 123456789 --task "установить Microsoft Office"
run.bat --id 123456789 --password "пароль_неконтролируемого_доступа" --task "почистить очередь печати"
run.bat                                   :: спросит ID и задачу
run.bat --id 123456789 --no-connect       :: сеанс уже открыт вручную — просто найти окно
run.bat --local --dry-run --task "..."    :: тест на своём ПК: только показывает, что сделал бы
```

Пример сеанса:

```
[ИИ] Понял задачу так: установить Microsoft Office на компьютер пользователя.
[ИИ спрашивает] Какая лицензия: Microsoft 365 по учётной записи или Office 2021/2024 с ключом?
  > Microsoft 365 для бизнеса
[ИИ] План:
   1. Открыть PowerShell от администратора
   2. Проверить, не установлен ли уже Office
   3. Скачать Office Deployment Tool и создать config.xml (O365BusinessRetail, ru-ru)
   4. Запустить установку и дождаться окончания
   5. Запустить Word и проверить
Enter — начать, или напишите поправку к плану:
[Шаг 1] думаю...
   Открываю PowerShell с правами администратора
   -> open_terminal powershell (admin)
   Выполнить? [Enter/y — да, n — пропустить, q — стоп, или напишите подсказку]:
...
```

### Управление во время работы

- **Ctrl+C** в консоли — пауза: продолжить, дать агенту подсказку, показать план или завершить.
- **Увести мышь в левый верхний угол экрана** — аварийная остановка (pyautogui failsafe).
- Режим подтверждений `--confirm` (или `[agent] confirm` в конфиге):
  - `risky` (по умолчанию) — спрашивать перед установкой/удалением ПО, удалением файлов,
    перезагрузкой, запуском от администратора и опасными командами (`Remove-Item`, `format`,
    `diskpart`, `reg delete`, `shutdown`…);
  - `all` — подтверждать каждое действие;
  - `none` — полностью автономно (не рекомендуется).
- Если ответ на подтверждение — не «y/n», а текст, он уходит агенту как подсказка
  («не удаляй профили, только temp»).

Каждый сеанс пишется в `logs/<дата_время>/`: скриншоты каждого шага с отмеченной точкой клика и
`session.jsonl` с планом, ответами модели и вашими ответами.

## Настройки AnyDesk

- На **вашем** AnyDesk: *Настройки → Ввод → «Передавать комбинации клавиш»* — иначе Win+R
  откроет «Выполнить» у вас, а не у пользователя. Синхронизация буфера обмена должна быть включена
  (по умолчанию включена) — через неё вводится текст, поэтому кириллица и любая раскладка
  у пользователя не проблема.
- Окно сеанса лучше развернуть на весь экран: чем крупнее картинка, тем точнее клики.
- Окна UAC («Разрешить этому приложению вносить изменения?») видны через AnyDesk, только если
  AnyDesk у пользователя **установлен**, а не просто запущен. Иначе экран станет чёрным — агент
  спросит вас, и пользователю придётся нажать «Да» самому.
- Если окно сеанса не находится автоматически, программа попросит кликнуть по нему; можно также
  задать часть заголовка в `[anydesk] window_title`.

## Ограничения и безопасность

- Подключайтесь только к компьютерам, владельцы которых согласились на удалённую помощь.
- Пароли и лицензионные ключи агент не придумывает — он спрашивает вас. Лучше, чтобы пароли
  вводил сам пользователь.
- Скриншоты экрана пользователя отправляются выбранному провайдеру модели. Если там могут быть
  персональные данные — используйте локальную Ollama.
- Оператор Windows-only: поиск окна AnyDesk сделан через `pygetwindow`. Режим `--local` работает
  и на Linux/macOS.

## Для разработчиков

```
anydesk_helper/
  __main__.py    CLI, проверка модели (--check)
  agent.py       план, цикл «скриншот → действие», вопросы и подтверждения, логи
  actions.py     разбор JSON от модели, проверка действий, правила подтверждения
  controller.py  мышь/клавиатура (pyautogui), ввод текста через буфер обмена
  screen.py      скриншоты (mss), масштабирование под Qwen (кратно 28 px), пересчёт координат
  anydesk.py     запуск AnyDesk, поиск окна сеанса, DPI
  llm.py         клиент OpenAI-совместимого API
  prompts.py     промпты и подбор методичек
playbooks/       методички по типовым задачам
```

Тесты (не требуют экрана и модели): `pip install pytest && python -m pytest`.
