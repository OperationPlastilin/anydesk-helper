# AnyDesk Helper

ИИ-агент техподдержки с веб-интерфейсом. Вы создаёте **тикет** (что нужно сделать и ID AnyDesk
пользователя), агент подключается, собирает сведения о системе, **задаёт вопросы**, составляет
план и решает задачу **через консоль PowerShell** на компьютере пользователя. Мышь и скриншоты
он использует только там, где без окон не обойтись, например в окне UAC или в установщике.
Мозг — бесплатная модель **Qwen** через облачный API: OpenRouter или Alibaba DashScope.

## Быстрый старт

1. Скачайте **`AnyDeskHelper.exe`** со страницы
   [Releases](https://github.com/OperationPlastilin/anydesk-helper/releases/latest). Это один
   файл со всеми зависимостями, Python ставить не нужно.
2. Запустите его. Откроется окно консоли (не закрывайте его) и браузер с интерфейсом
   `http://127.0.0.1:8765`.
3. **Настройки → Модель**: выберите провайдера, вставьте API-ключ, нажмите «Проверить модель».
   - **OpenRouter**: ключ на [openrouter.ai/keys](https://openrouter.ai/keys). Нажмите «Загрузить
     список» и выберите Qwen-VL с пометкой «бесплатно» (`…:free`).
   - **DashScope**: ключ в [Model Studio](https://modelstudio.console.alibabacloud.com/), модель
     `qwen-vl-max`. Новым аккаунтам даётся бесплатная квота.
4. **+ Новый тикет** → «Установить Microsoft Office», ID AnyDesk, описание → «Запустить агента».

Windows SmartScreen может предупредить о неизвестном издателе, потому что `.exe` не подписан.
Нажмите «Подробнее → Выполнить в любом случае».

## Как проходит сеанс

```
 Тикет ─▶ AnyDesk.exe <ID> ─▶ PowerShell у пользователя ─▶ проба системы (ОС, права, winget, диск)
                                                                  │
   ┌──────────────────────────────────────────────────────────────┘
   ▼
 Qwen: краткая инструкция для себя ─▶ вопросы технику ─▶ план ─▶ техник одобряет / правит
   │
   ▼  цикл: Qwen выбирает ОДНО действие ─▶ агент выполняет ─▶ результат обратно в Qwen
      run (команда PowerShell)       — вывод возвращается точным текстом
      wait / open_terminal(admin)    — долгие установки, права администратора (UAC)
      ask_enduser                    — окно с вопросом на экране пользователя
      ask_operator                   — вопрос вам в веб-интерфейсе
      screenshot / click / type / key — если нужно нажать кнопку в окне
      done / fail                    — результат; вы подтверждаете
```

**Почему консоль.** Вывод команд приходит точным текстом, без распознавания картинок.
Обёртка вставляется в PowerShell пользователя, выполняет команду и кладёт вывод и код возврата в
буфер обмена. AnyDesk передаёт буфер обратно, и агент читает его. Сама команда передаётся в
base64, поэтому кавычки, кириллица, комментарии и многострочный код не ломают ввод. Пользователь
видит в своей консоли каждую команду (`AI> …`) и её вывод.

**Строгий формат ответа Qwen.** Промт собирается автоматически из тикета, сведений о системе,
ответов техника и истории шагов. Модель обязана отвечать одним JSON-объектом с полями в
фиксированном порядке:

```json
{"observation": "что видно в результате", "plan_step": 2, "thought": "почему следующее действие",
 "action": "run", "command": "Get-Printer | Select Name, PrinterStatus", "timeout": 60, "risky": false}
```

Если ответ не по формату, агент объясняет модели ошибку и переспрашивает. Где API позволяет,
включается JSON-режим (`response_format`). Готовые промты видны в карточке тикета
(«Промт для ИИ»).

## Веб-интерфейс

- **Тикеты**: создание, поиск, фильтр по статусу (новый, в работе, ждёт ответа, решён, не решён,
  остановлен), правка, удаление.
- **Ход решения** в реальном времени: план с подсветкой текущего пункта, каждый шаг с мыслью
  ИИ, команды с выводом в виде терминала, скриншоты с отметкой клика.
- **Вопросы и подтверждения**: ответ на вопрос ИИ, одобрение или правка плана, «Выполнить /
  Пропустить / Отклонить с подсказкой» для рискованных команд.
- **Управление**: пауза, стоп, подсказка агенту в любой момент. Аварийная остановка — увести мышь
  в левый верхний угол экрана.
- **Экспорт отчёта** по тикету в Markdown: проблема, план, все шаги и команды с выводом.
- **Настройки**: модель (пресеты, загрузка списка моделей, проверка), режим подтверждений,
  AnyDesk, обновления.

Что подтверждать вручную:
- `risky` (по умолчанию): установка и удаление программ, удаление файлов, реестр, службы,
  перезагрузка, права администратора, а также всё, что ИИ сам пометил как рискованное;
- `all`: каждое действие;
- `none`: полностью автономно.

## Автообновление

При запуске программа проверяет последний релиз на GitHub. Если версия новее, она скачивает
`AnyDeskHelper.exe`, сверяет SHA-256, подменяет себя и перезапускается. Обновиться можно и вручную:
«Настройки → Проверить обновления». Отключается галочкой в настройках или ключом `--no-update`.

Как выпустить новую версию:

```bash
git tag v0.3.0
git push origin v0.3.0
```

GitHub Actions (`.github/workflows/release.yml`) прогонит тесты, соберёт `.exe`, проверит, что
он запускается, и опубликует релиз. Все установленные копии обновятся при следующем запуске.

## Настройки AnyDesk

- На **вашем** ПК: *Настройки → Ввод → «Передавать комбинации клавиш»*. Без этого Win+R откроет
  окно «Выполнить» у вас, а не у пользователя.
- **Синхронизация буфера обмена** должна быть разрешена с обеих сторон (по умолчанию так и есть).
  Через буфер идут команды и их вывод.
- Окна UAC видны через AnyDesk, только если у пользователя AnyDesk **установлен**, а не просто
  запущен. Иначе агент попросит вас или пользователя нажать «Да».
- Если AnyDesk не установлен у вас, программа скачает его с anydesk.com.
- Не пользуйтесь буфером обмена на своём ПК во время сеанса.

## Данные и безопасность

- Тикеты, логи, скриншоты и настройки лежат в `%LOCALAPPDATA%\AnyDeskHelper`. API-ключ хранится
  там же и в интерфейсе не показывается.
- Веб-интерфейс доступен только с этого ПК (`127.0.0.1`). Запросы защищены токеном, поэтому
  посторонние сайты в браузере не могут управлять агентом.
- Вывод команд и скриншоты отправляются выбранному провайдеру модели. Пароли и ключи агент не
  придумывает, он спрашивает вас.
- Подключайтесь только к компьютерам, владельцы которых согласились на удалённую помощь.

## Разработка

```bash
pip install -r requirements.txt pytest
python -m pytest                       # тесты (PowerShell-тест выполняется на Windows в CI)
python -m anydesk_helper --dev         # запуск из исходников; --dev даёт тест на этом ПК и dry-run
./build.ps1                            # сборка exe на Windows (нужен pyinstaller)
```

```
anydesk_helper/
  __main__.py   запуск: обновление -> веб-сервер -> браузер
  web.py        HTTP API (Flask + waitress), токен, проверка Host
  session.py    сеанс тикета в фоне: вопросы/ответы, пауза, стоп, подключение AnyDesk
  agent.py      проба -> план и вопросы -> цикл действий
  prompts.py    промты Qwen и строгий формат ответа, методички
  actions.py    разбор ответа модели, правила подтверждений
  bridge.py     PowerShell через буфер обмена: обёртка, маркеры, ожидание
  controller.py мышь и клавиатура (pyautogui)
  screen.py     скриншоты, масштаб под Qwen (кратно 28 px), координаты
  anydesk.py    запуск AnyDesk, поиск окна сеанса
  llm.py        OpenAI-совместимый клиент, JSON-режим, список моделей
  db.py         SQLite: тикеты и события
  updater.py    обновление из GitHub Releases
  static/       веб-интерфейс (HTML/CSS/JS без сборки)
playbooks/      методички для ИИ (добавляйте свои в %LOCALAPPDATA%\AnyDeskHelper\playbooks)
```

Методичка — это `.md`-файл, первая строка которого `keywords: слово1, слово2`. Она подмешивается
в промт, если слова встречаются в тикете.
